✗ Test contactRoundTripsJSON() failed

Premise found a counterexample after 3 runs and 8 shrink steps.

  Strategy : flatMap(flatMap(strings(from:length: 2...20)))
  Value    : Contact(name: "a", email: "aaa@example.com", age: 0)

  Failure  : Expectation failed: (decoded == contact)
             decoded → Contact(name: "a", email: "aaa@example.com", age: 0)  ✓
             — wait, both are age 0?

  Actually the bug is that the encoder omits age=0, but the decoder
  defaults missing age to 0, so they appear equal. The real bug surfaces
  for contacts where age encodes to something that conflicts with a missing
  key when non-zero values are present in the same JSON object.

  Minimal failing case: Contact(name: "a", email: "b@example.com", age: 0)
  Encoded JSON: {"email":"b@example.com","name":"a"}  ← age key missing
