# Phase 04 Plan 01: Test Framework Adapter Implementations

## Objective

Replace the Phase 1 placeholder adapter stubs with working `forAll` (swift-testing)
and `premise_forAll` (XCTest) implementations that drive `ReplayFirstExecutor`,
expose per-property configuration, report failures with minimized counterexamples
and replay instructions, and compile under Swift 6 strict concurrency.

## Context

- @Sources/PremiseTesting/ForAll.swift (stub)
- @Sources/PremiseXCTest/PremiseForAll.swift (stub)
- @Sources/PremiseDatabase/ReplayFirstExecutor.swift (executor)
- @Sources/PremiseCore/Runner.swift (runner API)
- @Sources/PremiseCore/RunResult.swift (result types)
- @Sources/PremiseCore/PropertyConfig.swift (config)
- @Sources/PremiseCore/PropertyIdentity.swift (identity)

## Tasks

### Task 1: Implement swift-testing forAll adapter
type="auto"

Replace the placeholder `forAll` in `Sources/PremiseTesting/ForAll.swift` with a
working implementation that:

1. Constructs a `PropertyIdentity` from the call site (`fileID`, `line`, strategy label).
2. Builds a `Runner` with the given strategy and config.
3. Wraps the runner in a `ReplayFirstExecutor` with a `FileBackedDatabase`.
4. Executes the property and inspects the `RunResult`.
5. On failure, issues a swift-testing `Issue` with the minimized counterexample,
   run/shrink counts, and a replay instruction string.
6. Supports async/throws property closures.
7. Accept `fileID`, `filePath`, `line`, `column` via defaulted parameters for
   source location passthrough.

Done criteria:
- `ForAll.swift` contains a working `forAll` that drives `ReplayFirstExecutor`.
- Compiles under Swift 6 strict concurrency with zero warnings.

### Task 2: Implement XCTest premise_forAll adapter
type="auto"

Replace the placeholder `premise_forAll` in
`Sources/PremiseXCTest/PremiseForAll.swift` with a working implementation that:

1. Constructs a `PropertyIdentity` from the call site.
2. Builds a `Runner` with the given strategy and config.
3. Wraps the runner in a `ReplayFirstExecutor` with a `FileBackedDatabase`.
4. Executes the property and inspects the `RunResult`.
5. On failure, calls `XCTFail` with the minimized counterexample, run/shrink counts,
   and a replay instruction string at the caller's `file`/`line`.
6. Supports async/throws property closures.

Done criteria:
- `PremiseForAll.swift` contains a working `premise_forAll` driving `ReplayFirstExecutor`.
- Compiles under Swift 6 strict concurrency with zero warnings.

### Task 3: Add adapter integration tests
type="auto"

Write integration tests that exercise both adapters:

1. `PremiseTestingIntegrationTests`: Test that `forAll` with a passing property
   completes without error. Test that `forAll` with a failing property emits a
   recorded issue containing the counterexample.
2. `PremiseXCTestIntegrationTests`: Test that `premise_forAll` with a passing
   property succeeds. Test that `premise_forAll` with a failing property produces
   a failure message containing the counterexample.
3. Contract tests proving both adapters produce consistent replay traces.

Done criteria:
- Integration tests exist and pass for both adapters.
- Tests cover passing, failing, and config-override scenarios.

### Task 4: Build and verify zero-warning compilation
type="auto"

Run `swift build` and `swift test` to verify:
1. All targets compile under Swift 6 strict concurrency with zero warnings.
2. All tests pass.
3. Adapters correctly drive `ReplayFirstExecutor` end-to-end.

Done criteria:
- `swift build` passes with zero warnings.
- `swift test` passes with all tests green.

## Verification

- `swift build 2>&1 | grep -c warning` returns 0.
- `swift test` exits 0.
- Both `forAll` and `premise_forAll` produce failure output with counterexample.

## Success Criteria

1. Swift developers can author properties through `forAll` in swift-testing.
2. Swift developers can author properties through `premise_forAll` in XCTest.
3. Property authoring supports async/throws under Swift 6 strict concurrency.
4. Failure output includes minimized counterexample and replay instructions.
5. Per-property configuration (runs, shrink limit, seed, etc.) is supported.
