Create `SQLiteBackedDatabase.swift` implementing `ExampleDatabase` as an actor.

```swift
import PremiseCore
import Foundation
import SQLite3

/// SQLite WAL-backed failure store implementing the ``ExampleDatabase`` contract.
///
/// The actor owns a single ``SQLiteConnection`` and serializes all reads and
/// writes through the actor mailbox. Records are stored with explicit
/// `trace_format_version` and `record_format_version` columns so that
/// compatibility can be validated before decode.
public actor SQLiteBackedDatabase: ExampleDatabase {
    private let connection: SQLiteConnection

    /// Opens (or creates) a SQLite database at `path`.
    ///
    /// - Parameter path: Filesystem path to the `.sqlite` file.
    ///   Defaults to `.premise/examples.sqlite`.
    /// - Throws: ``SQLiteError`` if the runtime is WAL-unsafe, if the file
    ///   cannot be opened, or if schema creation fails.
    public init(path: String = ".premise/examples.sqlite") throws {
        self.connection = try SQLiteConnection(path: path)
    }
}
```

Implement `save(_ record: FailureRecord)`:
1. Encode the record through `PersistenceCodec.encode(record)` to get a `PersistedFailureRecordV1`.
2. JSON-encode the `trace` field (`record.trace`) to `Data` for the `trace_json` column.
3. JSON-encode the entire `PersistedFailureRecordV1` to `Data` for the `record_json` column.
4. Use a prepared statement (`sqlite3_prepare_v2`) with `INSERT INTO failures (property_file_id, property_line, strategy_label, trace_format_version, record_format_version, trace_json, record_json, created_at_unix_ms) VALUES (?, ?, ?, ?, ?, ?, ?, ?)`.
5. Bind parameters with `sqlite3_bind_text`, `sqlite3_bind_int`, `sqlite3_bind_int64`, `sqlite3_bind_blob`.
6. `sqlite3_step` and `sqlite3_finalize`.
7. Throw `SQLiteError.resultCode` on non-`SQLITE_DONE`.

Implement `loadTraces(for id: PropertyIdentity)`:
1. Prepare `SELECT trace_format_version, record_format_version, trace_json FROM failures WHERE property_file_id = ? AND property_line = ? AND strategy_label = ? ORDER BY created_at_unix_ms ASC`.
2. Bind property identity fields.
3. Step through rows. For each row:
   a. Read `trace_format_version` and `record_format_version` as Int.
   b. Validate both versions against `PersistenceVersionPolicy` ranges — throw `PersistenceCompatibilityError` if outside range.
   c. Decode `trace_json` blob to `ChoiceTrace` via `JSONDecoder`.
4. Finalize statement, return `[ChoiceTrace]`.

Implement `clear(for id: PropertyIdentity)`:
1. Prepare `DELETE FROM failures WHERE property_file_id = ? AND property_line = ? AND strategy_label = ?`.
2. Bind, step, finalize. Throw on error.

Extract shared helpers as private methods:
- `private func prepareStatement(_ sql: String) throws -> OpaquePointer` — wraps `sqlite3_prepare_v2`, throws `SQLiteError.resultCode` on failure
- `private func bindPropertyIdentity(_ stmt: OpaquePointer, _ id: PropertyIdentity, startingAt: Int32)` — binds fileID, line, strategyLabel to consecutive parameter slots

No `fatalError`, no force-unwrap. Every `OpaquePointer?` from sqlite3 calls must
be safely unwrapped with guard/throw. Always finalize statements in defer blocks.

Timestamp column uses `Int64(record.timestamp.timeIntervalSince1970 * 1000)`.

**All tests in this task are conditional on `SQLiteRuntimeGate.isWALSafe()`.** If
the runtime is unsafe, tests should skip (use `try XCTSkipUnless(SQLiteRuntimeGate.isWALSafe(), "SQLite runtime below WAL-safe boundary")` or the Swift Testing `#require` equivalent from the existing test patterns).

Check existing test files to determine whether the project uses Swift Testing
(`import Testing`, `@Test`) or XCTest. Follow the same pattern.

**SQLiteBackedDatabaseTests.swift** — round-trip tests:

1. `testSaveAndLoadRoundTrip`: Create a `FailureRecord` with known values, save to
   a temp-file SQLite database, load traces for same property identity, assert the
   loaded `ChoiceTrace` equals the original record's trace.

2. `testLoadTracesReturnsEmptyForUnknownProperty`: Load traces for a property
   identity that was never saved, assert empty array returned.

3. `testClearRemovesRecords`: Save a record, clear for same property identity, load
   traces, assert empty array.

4. `testMultipleRecordsSameProperty`: Save two records for the same property
   identity, load traces, assert two traces returned in insertion order.

5. `testSaveAndLoadPreservesAllFields`: Save a record, then query the raw SQLite row
   (open a second read on the same file) to verify `property_file_id`,
   `property_line`, `strategy_label`, `trace_format_version=1`,
   `record_format_version=1`, and `created_at_unix_ms` are correct.

Use a temporary directory for each test (create with `FileManager.default.temporaryDirectory`
appending a UUID, clean up in teardown).

**SQLiteV1CompatibilityTests.swift** — backward compatibility:

1. `testV1EnvelopeImportThroughSQLite`: Create a `PersistedFailureRecordV1` using
   `PersistenceCodec.encode(record)`, manually insert it into a SQLite database
   (encoding trace and full record as JSON blobs with `traceFormatVersion=1` and
   `recordFormatVersion=1`), then call `loadTraces` on `SQLiteBackedDatabase` and
   verify the trace matches the original.

2. `testUnsupportedFutureTraceVersionThrows`: Manually insert a row with
   `trace_format_version=99` into the failures table, call `loadTraces`, assert
   it throws `PersistenceCompatibilityError.unsupportedTraceVersion(found: 99, supported: 1...1)`.

3. `testUnsupportedFutureRecordVersionThrows`: Manually insert a row with
   `record_format_version=99`, call `loadTraces`, assert it throws
   `PersistenceCompatibilityError.unsupportedRecordVersion(found: 99, supported: 1...1)`.

4. `testFileBackedAndSQLiteProduceSameTraces`: Create a `FailureRecord`, save
   through `FileBackedDatabase`, load traces from file-backed, save same record
   through `SQLiteBackedDatabase`, load traces from SQLite, assert both arrays of
   `ChoiceTrace` are equal.

For manual row insertion in compatibility tests, use `sqlite3_prepare_v2` /
`sqlite3_bind_*` / `sqlite3_step` / `sqlite3_finalize` directly (import SQLite3
in test file).
