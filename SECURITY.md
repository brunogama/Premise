# Security Policy

## Supported Versions

| Version | Supported |
| ------- | --------- |
| `main` (unreleased) | :white_check_mark: |
| tagged releases | not available yet |

## Reporting a Vulnerability

We take the security of Premise seriously. If you discover a security
vulnerability, please follow these steps:

1. **Do not** open a public GitHub issue.
2. Create a private GitHub security advisory when the repository supports it.
3. If private advisories are unavailable, contact the maintainers privately
   before public disclosure.
4. Include:
   - a description of the vulnerability
   - steps to reproduce the issue
   - potential impact
   - any suggested fix or mitigation

## Response Timeline

- We will acknowledge receipt within 48 hours.
- We will provide a detailed response within 5 business days.
- We will work with you to understand and resolve the issue.
- We will coordinate disclosure timing with you.

## Security Best Practices

When using Premise:

- Keep dependencies up to date.
- Use a supported Swift toolchain.
- Avoid checking persisted failing traces into public repositories unless you
  intend to share them.
- Be cautious when property tests exercise external systems or untrusted input.

## Vulnerability Disclosure

We believe in responsible disclosure. We will:

- Work with security researchers to understand and fix issues.
- Provide credit to researchers who report vulnerabilities when desired.
- Publish security advisories for confirmed vulnerabilities.
- Release patches in a timely manner.

Thank you for helping keep Premise secure.
